# LLM 提示词写作与治理

核心原则：**约束要"可执行"，不要"纯禁令"。** AI 需要知道"该做什么"，而不只是"不许做什么"。

## 一、语法分档（先判断句子复杂度，再选句式）

**关键前提**：句式选择取决于**原句本身是否复杂**，不是机械套模板。

### 1. 简单明确的禁令 → 保持原样，不要改写
短小、无歧义、读者一眼就懂的硬性规则，**不要**额外补"否则……"长解释——解释只会增加噪声。

- 正确（保持原样）：`禁止 <script>、事件属性、外部图片引用、<use>、url(http...)`、`只返回 JSON 本身，不要任何前后解释、不要 markdown 代码块`、`直角……不要画成弧`
- 反例（过度改写，应避免）：`禁止 <script>` → `必须不使用 <script>…；否则图形会被渲染器拦截而完全不显示` —— 这是生搬硬套，越改越啰嗦

### 2. 复杂条件/多重禁止 → 用"必须 X，不得 Y，否则 Z"
当原句是"**在什么……的条件下**"或"**……不要做……**"这类**太复杂**的描述（含条件、含多重动作、含歧义）时，才改写成消歧句式：

- `……必须……`：给出正向目标动作
- `……否则……`：给出违规后果
- `……应该……`：给出推荐做法（非强制的软约束）
- `……而不是 / 不要 / 严禁……`：给出被否定的替代（紧跟"应该"之后，形成对照）
- `……仅当 / 只有 / 只许……`：给出严格限定条件

改写示例：
- `交叉处若非连接点不要画实心点` → `必须用横平竖直的折线连接各元件；交叉处若非连接点，不得画实心点，否则会被误判为连通节点`
- `如果前面是 JSON……不要重新开始一个新的 JSON` → `必须严格延续原有格式：前面是 JSON 就继续合法的 JSON 文本（注意正确闭合字符串、数组与花括号）；不得重新开始一个新的 JSON`

### 3. "限制处缺怎么做" → 补正向动作
一句话里只有禁令、没有"该怎么做"时，在禁令前补一个正向动作，形成"**应该 X，而不是 Y**"的对照：

- `不要编造 URL` → `拿不准时应该留空字符串（交给检索兜底），而不是编造 URL`
- `不编造` → `不确定的地方应该明确说明"此处存疑"，而不是编造`
- `不得硬填一个无关的图` → `应该改用 imageData 或 SVG 表达，而不是硬填一个无关的图`

## 二、输出前的自检要求（AI 不主动检查，必须显式要求）

AI 生成复杂产物（如图形、代码、表格、试题答案）后**不会主动核对**，必须在 prompt 里显式加"自检清单"，要求它在输出前逐条核验：

- 写"**输出前必须逐条核对**"，并给出具体的检查项（用"**必须**"逐条列）
- 检查项要**可判定、可对号**，而不是"请确保正确"这种空话
- **每条检查项都要带"怎么检查"（检查方法）**，不能只列"检查什么"——例如不能只写"点是否画对"，要写"把点坐标代入它应在的线/圆的方程，看是否成立"
- **自检项按"类型/学科"拆分，只让 AI 看高度相关的那部分**：当自检项覆盖多个不相干的场景（如几何/函数/电路/受力/光学五类图），必须拆成「通用自检（必查）+ 分场景自检（只查当前那类）」，并**明确要求"只套用与当前产物相关的条目，无关条目不要套用、不要去想"**——否则无关内容会干扰 AI 对当前输出的判断
- 覆盖四类错：**缺元素**（该接的没接上）、**错位置**（标记/代号标错地方）、**代号错位**（角的字母写到边中间、边长代号写到顶点、力的符号落到别的力上、元件代号标到别的元件旁）、**数值不一致**（图/表与题干数据对不上，且"60° 就要看起来是 60°、不能画成 30° 的样子"）
- 结尾要求"**发现任何一处对不上，必须回到对应步骤重做，而不是带着错误输出**"

SVG 自检清单示例（拆为「通用 + 分学科」，每条带"检查方法"）：

**通用自检（任何图都查）**
1. **字母代号的位置是否正确**：角的字母（∠A/A）写顶点旁不能写边中间、边的字母（a/b/c）写边中点旁不能写顶点、力的符号标箭头旁、元件代号标元件旁、x/y/O 各归其位 → 逐个字母问"它代表哪个对象，是否紧邻该对象"
2. **数值一致**：图上 60° 就必须看起来是 60°、不能画成 30° 的样子 → 题干数值逐条抄出与图中标注对照
3. **没有多余元素**：题干没有的点/线/标注必须没有

**分学科自检（只查当前图那类）**
- 几何图：点是否画在线上（顶点落边端点、圆心等距、交点重合、直径端点落圆周）→ 把点坐标代入线/圆方程
- 函数图：是否过对点、是否在对象限 → 题干坐标代入函数式 + 对照斜率/二次项符号
- 电路图：元件两引脚是否都接导线、非连接点交叉是否跳线 → 沿电流路径从正极走一遍回路
- 受力图：力是否从作用点出发、方向是否正确 → 对每个力确认起点在作用点、方向符合性质
- 光学图：法线是否过入射点且垂直镜面、入射角=反射角 → 核对法线与角度关系

## 三、反例措辞要"通常化"

写反例时用**跨情形都成立的通常表述**，不要用具体数值特例：

- 好：`答案是 1，解析却是 2`（覆盖一切"答案与解析矛盾"）
- 差：`答案写 9W、解析算出 8W`（只记住这一个特例）

## 四、模板字符串安全（写进代码的 prompt 必读）

若 prompt 是 JS/TS **模板字符串**（反引号包裹），改写时：
- **绝不能引入反引号**，否则会截断字面量，esbuild 报 `Expected ";" but found "url"`
- `<script>` 这类标签只写尖括号，不加反引号
- 若用 `toContain` 做提示词契约测试，原文含 markdown 加粗时**必须保留 `**`**，否则断言失配

## 五、执行流程

1. 通读 prompt 全文，标记每处"限制/禁令"句子
2. 对每处按"§一"三档判断：保持原样 / 改写为"必须…否则…" / 补正向动作
3. 检查是否需要补"§二 自检清单"（涉及 AI 自主生成复杂产物的场景必加）
4. 改完跑 `tsc --noEmit` 与 `vitest run`，同步更新受影响的提示词契约断言
