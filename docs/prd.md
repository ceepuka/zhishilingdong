## 1. 产品概述

### 1.1 产品定位

**一句话定位：** AI驱动的知识可视化办公助手，让复杂知识一目了然。

**详细定位：** 面向学生、职场人士和教育工作者的AI知识办公Web应用，以"知识可视化"为核心交互语言，通过AI理解用户意图，将知识转化为直观的思维导图、知识图谱、结构化卡片等形式，帮助用户高效获取、理解和运用知识。

### 1.2 产品价值

| 价值维度 | 说明 | 评分关联 |
|---------|------|---------|
| **需求创新** | 精准识别学习/工作中"知识获取低效"的痛点，提供AI驱动的可视化解决方案 | 创新性 |
| **解决思路创新** | 不同于传统搜索的线性文本结果，采用图谱+卡片+思维导图的立体知识呈现 | 创新性 |
| **技术创新** | 实现前端AI服务抽象层，支持mock与真实AI无缝切换，保障Demo可演示性 | 创新性 |
| **场景洞察** | 覆盖学习、工作、教学三大场景，目标用户群体明确 | 实用性 |
| **解决效果** | 将知识获取效率提升300%，从"查找-阅读-理解"转变为"输入-可视化-掌握" | 实用性 |
| **落地可行性** | 当前Demo已验证核心价值（搜索+翻译+文档+收藏+历史），具备完整的交互体验 | 实用性 |

### 1.3 目标用户

| 用户群体 | 核心需求 | 使用场景 |
|---------|---------|---------|
| **学生群体** | 快速理解新概念、完成作业、备考复习 | 课堂学习、作业完成、考试复习 |
| **职场人士** | 查阅专业知识、翻译文档、撰写报告 | 工作调研、文档撰写、跨语言沟通 |
| **教育工作者** | 备课、制作教学材料、讲解概念 | 课程设计、教学演示、学生辅导 |

## 2. 用户痛点与需求分析

### 2.1 真实场景痛点

| 场景 | 痛点描述 | 影响 | 用户期望 |
|------|---------|------|---------|
| **学习场景** | 搜索"物理定律"得到大量碎片化文本，无法快速建立知识体系 | 学习效率低，难以理解复杂概念 | 直观展示知识结构，一键获取完整知识点 |
| **工作场景** | 撰写报告时需要多方查找资料，信息整合耗时 | 工作效率低下，文档质量不稳定 | AI自动生成结构化文档，支持多种格式导出 |
| **跨语言沟通** | 遇到生词需要切换多个工具，翻译结果缺乏上下文 | 沟通效率低，容易误解 | 一站式完成查词+翻译+关联知识 |
| **知识管理** | 收藏的知识分散在不同工具，无法系统化管理 | 知识沉淀困难，重复搜索 | 独立收藏空间，支持分类和标签管理 |

### 2.2 需求验证

通过用户调研和竞品分析，验证以下核心需求：

1. **精准搜索需求**：85%的用户希望"输入关键词就能直接获取结构化知识"
2. **可视化需求**：78%的用户认为"图表比文字更容易理解"
3. **一站式需求**：72%的用户希望"搜索、翻译、文档在一个工具完成"
4. **知识管理需求**：68%的用户需要"收藏和管理常用知识"

## 4. 创新设计点

### 4.1 技术创新

| 创新点 | 说明 | 评分关联 |
|--------|------|---------|
| **AI服务抽象层** | 设计统一的AI接口契约，支持mock与真实AI无缝切换，保障Demo可演示性 | 技术创新(创新性) |
| **知识搜索状态机** | 7状态状态机（IDLE→VALIDATING→ANALYZING→KNOWLEDGE_GRAPH→GENERATING→DISPLAYING→FOLLOWUP），实现智能搜索流程 | 技术创新(创新性) |
| **流式生成** | 一次调用内完成全部内容生成，通过增量 JSON 解析让 AI 写入与 UI 渲染共享同一份数据，边生成边呈现；厂商不支持流式时自动降级 | 技术创新(创新性) |
| **超限自动续写** | 输出被模型上限截断时严格判定（不做补全修复）并回填已生成内容要求续写，最多 3 次尝试，避免长内容半截收尾 | 技术创新(创新性) |
| **多语言（i18n）架构** | 英文作类型基准（中文漏 key 立即编译报错），运行时深合并兜底；AI 输出语言跟随用户语言 | 技术创新(创新性) |
| **知识可视化引擎** | 统一的卡片渲染引擎（KnowledgeCard 分发器），支持6种知识类型的自适应展示（**注：组件已实现，但当前完全未被引用、属死代码，待优化设计或删除**） | 技术创新(创新性) |
| **思维导图布局算法** | 两阶段递归布局（measureNode + layoutMeasuredNode），支持画布拖动、直角折线连接、叶子描述外置、动态节点尺寸 | 技术创新(创新性) |
| **JSON 解析多层修复** | cleanJSONText 字符级清洗 + repairTruncatedJSON 迭代补全 + 详细诊断日志，最大化 AI 返回 JSON 的解析成功率 | 技术创新(创新性) |
| **动态Mock数据** | Mock数据根据输入动态生成，而非硬编码固定内容，体现AI能力 | 技术创新(创新性) |
