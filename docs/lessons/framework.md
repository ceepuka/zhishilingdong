# 框架使用经验

## 2026-07-08（历史模块架构重构经验）

### 问题背景
三个功能模块（搜索、翻译、文档）各自实现了独立的历史侧边栏组件，导致：
- UI 不一致，修改需要同步 3-4 个文件
- props 传递链过长（App.tsx → Header.tsx → FavoritesPanel → 各模块）
- 重复代码多，维护成本高

### 解决方案
1. **提取通用组件**：创建 `HistorySidebar` 通用组件，支持主题色配置（teal/amber/blue）
2. **统一 API**：在 `useHistory` 中新增 `updateSession` 和 `getSession` 方法，替代分散的 session 方法
3. **状态自治**：各组件内部独立调用 `useTimeRefresh()`，消除外部 props 传递链
4. **删除冗余文件**：`TranslateHistory.tsx` 和 `DocHistory.tsx` 被通用组件替代

### 重构收益
| 指标 | 重构前 | 重构后 | 改善幅度 |
|------|--------|--------|----------|
| 修改历史记录 UI | 需要修改 3-4 个文件 | 需要修改 1 个文件 | 75%+ |
| 新增模块接入 | 需要编写新组件 | 只需配置 config | 80%+ |
| props 传递链长度 | 3-4 层 | 0 层 | 100% |

### 关键原则
- **DRY 原则**：相同的 UI 模式必须提取为通用组件
- **单一数据源**：API 统一避免逻辑分散
- **状态下推**：组件内部状态尽量在组件内部管理，避免向上传递
- **兼容层**：重构时保留原有方法作为兼容层，降低风险

### 适用场景
- 多个模块有相似 UI 组件时
- props 传递链超过 2 层时
- 需要统一 API 行为时

## 2026-09-14（i18n 文案里"被组件切分"的占位符要用契约测试钉住）

### 问题背景
页脚版权声明署名 GitHub 账号，需要把作者名渲染成可点击链接，但整句文案放在 i18n 字符串层（组件禁止裸字符串）。做法：文案写 `'© {year} {author} · 保留所有权利'`，组件 `split('{author}')` 切出作者名单独渲染成链接。

### 隐患
类型系统只能保证 key 存在、结构一致，**管不住字符串内容**。若将来有人改文案时删掉 `{author}`，`split` 返回长度 1 的数组，链接**静默消失**——不报错、不白屏，只是页脚少了一段，极难被发现。

### 解决方案
对"组件依赖其内部占位符做切分/特殊渲染"的文案，补**契约测试**钉住：
- 断言各语言版本的模板都含所需占位符（`{year}` / `{author}`）
- 断言切分 + `fmt` 填充后的实际结果（年号就位、作者名落在可链接的独立片段）

### 关键原则
- **i18n 占位符不只是格式填充，也可能是组件的切分锚点**——后者必须用测试固定
- 判据：只要组件对某段文案做了 `.split()` / 正则提取 / 条件分支渲染，就该有契约测试
- 这类缺陷的共性是"**静默降级**"（少一段 UI 而非报错），正是契约测试最该覆盖的类型
