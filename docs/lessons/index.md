## 近期教训

### 2026-09-14
- **`.gitignore` 不会取消已追踪文件**：`dist/` 的 64 个构建产物一直躺在版本库里，尽管 `.gitignore` 早已写了 `dist`——因为它们是**在加规则之前**就提交的，而 ignore 只约束"未追踪"文件。想彻底排除必须 `git rm -r --cached <dir>` 再提交。且**删前先确认该目录是否被构建/部署依赖**：本项目 `vercel.json`/`netlify.toml` 都由平台自行 `npm run build` 再取 `dist`，故仓库内 dist 属纯污染（详见 config.md）
- **清理要"先只读扫描、分三档、再动手"**：拿到"剔除垃圾文件"这类指令别直接删——`.trae/` 是 Trae 项目级 Skill 的**必需目录**（不是垃圾）、`remotion-videos/public/assets` 是 11MB 视频素材、`output/*.mp4` 是成品，误删代价高。正确姿势：只读扫描出清单（规模 + git 追踪状态）→ 报告 → 分「可删 / 待定夺 / 必留」→ 确认后执行；只把**可再生**的（构建产物、配置快照）归入可删。呼应既有教训"不确定用途的外部文件不要擅自删除"。环境坑：`Add-Type` 被安全策略拦，PowerShell 送回收站方案不可用，需退回直接删除（详见 config.md）
- **i18n 文案里"被组件切分"的占位符要用契约测试钉住**：页脚版权需把作者名渲染成链接，做法是文案写 `'© {year} {author} · 保留所有权利'`、组件 `split('{author}')` 切出作者名。类型系统管不住字符串内容——占位符被删时 `split` 只返回一段，链接**静默消失**（不报错、只是少一段 UI）。判据：只要组件对某段文案做了 `.split()` / 正则提取 / 分支渲染，就该补契约测试断言占位符存在 + 切分填充后的实际结果（详见 framework.md）

### 2026-09-12
- **"吞错器"会让下游错误处理变成死代码**：`withFallback` 把任何异常都 catch 成 `success:true` 的空结构体，导致状态机里针对 `StreamTimeoutError` 的识别**永远走不到**，用户只看到笼统"生成失败"。兜底层必须区分语义 —— 业务错误可兜底，链路/传输错误应透传为 `success:false + code`（详见 logic.md）
- **同一语义不要有两套实现**：续写判定与解析层各写一套括号配对，先出现"只判 `{}` 漏判 `[]`"的边界 bug（`{"a":[1,2}` 被误判完整、跳过续写）。凡"完整性/有效性判定"都应指向同一权威实现（`isCompleteJSON`），并在"括号闭合"之上补语义判据（核心字段齐全）（详见 logic.md）
- **思考型模型的默认思考必须显式关闭，且参数逐厂商核对**：智谱 GLM-5.2 默认开思考，思维链吃掉 `max_tokens` 总预算致正文截断（"智谱总是生成失败、千问正常"）；关闭思考的字段名逐厂商不同（智谱 `thinking:{type:'disabled'}`，传 `thinking:false` 会 400），必须核对官方文档、按厂商白名单分派（详见 logic.md）
- **约束 LLM：负面限制不如正向可执行教学**：写"别画错""要准确"模型无从执行；必须给正向的、分步骤的做法（画几何图先定顶点坐标→按对边命名→补符号标记）与反例句 + 判定准则（"答案与解析不一致""不确定就 `examQuestions:[]`"）（详见 logic.md）
- **提示词句式改写必须按原句复杂度分档**：只有"条件句 / 多重禁止"这类难读的描述才值得改写成"必须 X，不得 Y，否则 Z"；短小明确的硬性规则（`禁止 <script>`、`只返回 JSON 本身`、"不要画成弧"）**保持原样最好**——机械套句式 + 补长解释纯属噪声（被用户点名为"过度改写、生搬硬套"）。反例措辞要"通常化"（"答案是 1、解析却是 2"优于"9W/8W"）（详见 logic.md）

### 2026-09-13
- **约束要补正向动作，且显式要求 AI 自检**：限制句只写禁令不写"该怎么做"，模型无从执行（"不要编造 URL"→"应该留空字符串，而不是编造 URL"）；AI 生成复杂产物后**不会主动核对**，必须在 prompt 里显式加"输出前必须逐条核对"的自检清单（关键点闭合 / 标记对号 / 数值一致 / 符号规范 / 没有多余元素），并写"发现对不上就重做，而不是带错输出"。**自检项本身也要带"检查方法"**——不能只写"点是否画对"，要写"把点坐标代入应在的线/圆方程看是否成立"。**字母代号位置也要单独检查**（角的字母写顶点旁不能写边中间、边长代号写边中点旁不能写顶点、力的符号标箭头旁、元件代号标元件旁）。**自检项要按学科/类型拆分**，只让 AI 看与当前产物高度相关的那部分、明确"无关条目不要套用"，避免无关内容干扰 AI 判断（详见 logic.md）
- **输入意图判定：拿不准降级、分类开放兜底、校验从宽**：把"热梗/角色名/游戏设定/口语"明确纳入非知识点走问答（问答失败成本最低，"拿不准就判 false"）；学科分类用"推荐清单 + 交叉学科取交叉归属 + '其他'兜底"而非封闭枚举；`validate` 只拦真正乱敲、拿不准一律放行（详见 logic.md）
- **分类结果要驱动下游、历史命中用归一化键、数据迁移新旧兼容**：`category`/`knowledgeType` 只产出不消费等于白分类，应定制生成提示词（且只注入相关学科、交叉学科不套单一规则）；历史命中必须用 analyze 出的 `canonicalTopic` 而非原始输入；收藏迁到新格式时读取端要同时兼容 `topic`/`title` 两套字段；非知识点判定用"闭合标准"（确信能讲出体系才判 true）而非"逐类枚举"（详见 logic.md）
- **AI 产出字段要全链路闭环（否则静默空白）**：一个字段从 prompt（要求产出+JSON 示例）→ 类型 → 清洗（sanitize 兜底）→ 状态机 → UI 五段缺一不可；知识图谱"不显示"的根因就是 `graphData` 在类型/状态机/UI 都备好了、唯独 prompt 没让模型产出。新增字段要逐环核对，且 prompt 的返回 JSON 示例必须包含它（详见 logic.md）
- **统一渲染入口要覆盖所有渲染路径（对话是独立路径）**：公式渲染在 `SearchResults` 全覆盖后，对话的 `QASection` 仍用 `{msg.content}` 裸输出、公式又露源码——因为对话是独立渲染路径，改主链路不等于全覆盖。`LatexText` 要穷举所有含 AI 文本的组件（生成卡片/对话/收藏详情/导出）逐一接入，且 Prompt 层（`buildFollowupSystemPrompt`）也要补 `$...$` 约定（渲染层+Prompt 层双保险）（详见 logic.md）
- **"原样输出、绝不吞内容"要配视觉信号 + Prompt 防御要写"具体怎么错"**：KaTeX 失败时只做"原样输出"对屏幕阅读器/复制/测试是安全的，但对用户视觉体验是"页面 bug"——给 KaTeX 失败段包 `<code class="latex-fallback">`（等宽字体+浅琥珀背景+左侧细色条+`title="公式源码（未能渲染）"`）双得：textContent 不变、用户有明确信号。Prompt 防御要给"具体怎么错"的反例（如 `'\frac' 不能写 'rac'`），模型才能识别"错的形态"（详见 logic.md）
- **模板字符串里写 LaTeX 反例要防"反斜杠被解析"**：源里 `'\frac'` 会被 JS 解析成 form-feed（`\f`）+ `rac`，运行时反斜杠消失；必须源里写 `'\\frac'`（双反斜杠）才得到运行时单反斜杠。这与"反引号"陷阱同类——模板字符串里的转义字符会被吃，写完用 `node -e` 验证运行时字符串（详见 logic.md）
- **解析/开放文本字段要"总闸式"禁止离题**：`explanation` 这类自由书写字段，只约束"与答案一致"（管结论正确）管不住过程里夹带的废话——会出现"几道经典题""信雅达千字文""采用 2022 年全国乙卷真题"等离题乱编、多套解法交织。要加一条总闸式禁令（只写本题推导、一套解法，严禁自我标榜/罗列多题/引言点评），并在字段级说明 + 严谨性铁律双写；续写提示词也要补"不得推翻前文"，防续写轮重述/改写前文造成多套解法交织（详见 logic.md）

### 2026-09-11
- **AI 内容渲染入口必须统一 + 防御性回退**：同一类数据要么全部走同一个渲染器、要么全部别用，零散接入是漏洞温床。`splitBareLatex` 只认强信号、必须 KaTeX 解析成功才渲染（既防 `snake_case` 误识别也防 `C:\Users` 伪命中），失败回退原文绝不吞内容 —— 最坏是回到原文，不出错位。配套：prompt 源头加固"凡数学符号一律 `$...$` 包裹"作为双保险的第一层（详见 logic.md）
- **带"自愈"承诺的熔断/缓存必须保证自愈入口可达**：把"冷却"实现成"永久禁用"，会使"流式成功即移出"的自愈逻辑永远走不到；症状与实现距离远、进程内缓存刷新即恢复，极难定位。配套：运行时降级必须 `console.warn` 可观测，记账条件收敛到协议层证据，降级策略用可注入 `now` 做契约测试（详见 logic.md）
- **流式增量解析的"完成"判定必须覆盖所有值类型**：只处理字符串/字面量型值的收尾，会让数组/对象型字段在整个中间态缺失于 `completedKeys`，下游步骤指示永久卡住；且最终态有 `Object.keys` 兜底，常规测试发现不了 —— 增量解析的契约必须在"未闭合"状态下断言（详见 logic.md）
