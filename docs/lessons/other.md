# 其他错误

## 工具使用 - 同一文件严禁并行发起多个 Edit
- 时间：2026-09-06
- 场景：mock 数据全量升级时，同一消息对 mockData.ts 并行发起 4 个 Edit
- 错误：并行编辑产生竞态条件——多个 Edit 的 old_string 基于同一文件的不同版本匹配，工具均报告成功，但实际内容错位/丢失/乱码（字段交叉合并、`concepts: 'definition', title:...`、碎片拼接、文件尾部函数块重复 5 份），导致 tsc 报 TS1136/TS1128 等语法错误
- 正确做法：
  1. 同一文件的多个 Edit 必须严格串行：一条消息只发一个 Edit，等结果返回后再发下一个
  2. 不同文件的 Edit 相互独立，可并行
  3. 乱码修复时 old_string 必须先 Read 确认真实内容（乱码碎片无法凭记忆还原）
  4. 批量替换后用 Grep 验证（如旧格式 `content: '` 单引号字符串应无残留）
- 标签：工具使用, Edit, 竞态条件, 文件损坏

## 项目管理 - Skill 动态发现必须双路径搜索
- 时间：2026-07-07
- 场景：B3 任务完成后执行文档同步，判断「无 project-document-manager Skill」后直接编辑文档
- 错误：只搜索了项目 `.trae/skills/` 目录，遗漏了全局 `~/.trae-cn/skills/` 中的 Skill
- 原因：Skill 动态发现机制未明确规定搜索范围，默认只搜项目目录
- 正确：项目 `.trae/skills/`（项目专用）和全局 `~/.trae-cn/skills/`（用户全局）两个目录都必须检查
- 标签：项目管理, Skill发现, 工作流

## 项目管理 - 不确定用途的外部文件不要擅自删除
- 时间：2026-07-02
- 场景：模块化重构项目时，发现来源不明的截图文件和 Session ID.txt，直接计划删除
- 错误：未确认用户意见就计划删除外部来源不明的文件
- 正确做法：
  1. 将不确定用途的外部文件移动到 docs/external/ 目录
  2. 在 docs/external/README.md 中记录文件信息（文件名、发现时间、推测来源、当前状态）
  3. 询问用户处理意见（保留/归档/删除）
  4. 根据用户意见更新状态
- 标签：项目管理, 外部文件, 删除操作
