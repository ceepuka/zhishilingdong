# 项目文档管理配置

> 本文件是 project-document-manager Skill 在本项目的执行规范，必须被遵循。
> 基本模板即新项目初始化标准；本项目为已有项目，需配合现有文档结构使用。

## 产品生命周期阶段：开发期（未正式落地）⚠️

**当前阶段：开发期（Pre-launch）** —— 产品尚未正式发布、无线上用户、无存量数据。

本阶段所有开发工作遵循以下约束（优先级最高，与本文件其他规则冲突时以本节为准）：

1. **不考虑向后兼容**：接口签名、存储结构、组件 props 可直接修改，无需保留旧形态
2. **不写迁移逻辑**：LocalStorage/配置结构变更时直接升级，不写 v1→v2 迁移、旧 Key 兼容读取等代码
3. **不保留兼容层**：被替代的模块/函数/文件直接删除，不写 `@deprecated` 转发壳、不 re-export 旧入口
4. **不做冗余防御**：不为"可能存在的旧数据/旧调用方"加防御分支，保持代码最简
5. **重构即重写**：方案变化时允许直接重写而非渐进改造

**阶段切换条件**：产品正式发布（有真实用户和存量数据）后，本节切换为「运营期」，届时新增约束：破坏性变更必须提供数据迁移、废弃接口保留一个版本周期、删除文件前确认无外部引用。

> 原则：兼容性成本只应为真实用户和真实数据支付；开发期的每一行兼容代码都是技术债。

## 同步判断规则

### 不触发同步的改动（全部满足）
完全跳过，不更新任何文档：
1. 不改变任何函数签名/接口定义
2. 不改变控制流（条件分支、循环结构、返回语句）
3. 不改变输出结果或对外行为
4. 仅涉及以下内容：注释添加/修改、代码格式化、变量名重命名（不涉及调用处）、import 语句整理、配置文件中默认值微调

### 同步粒度区分
| 类型 | 适用场景 | 更新方式 |
|-----|---------|---------|
| 详细更新 | 新增功能、修改核心逻辑、修复Bug、架构变更、配置变更、需求变更 | 完整更新（事件+文件变更+关联文档） |
| 简要更新 | 单行逻辑修改、常量值调整、轻微样式调整、非核心配置变更 | 在 history.md 添加简短记录 |

## history.md 五段式格式

每次更新 history.md 时按以下格式记录：

```markdown
## YYYY-MM-DD（简短主题）

### 事件
- **变更点1**：描述
- **变更点2**：描述

### 文件变更
- 更新/新建/删除 `path/to/file`：变更内容

### 构建验证
- TypeScript 类型检查：通过/失败
- 生产构建：通过/失败

### 关联文档
- 更新 `docs/xxx.md`：变更说明

### 经验教训（可选）
- **教训标题**：描述
```

## 关键约束（本项目特定）

1. **产品处于开发期**：未正式落地，不考虑向后兼容、不写迁移逻辑、不保留 deprecated 兼容层（详见本文件顶部「产品生命周期阶段」一节）
2. **PRD 是需求唯一真实来源**：所有功能需求、优先级、验收标准以 `docs/prd.md` 为准
3. **功能完成判定**：必须在 PRD 和 goal.md 中如实标注，未完成功能不得声称已完成
4. **死代码处理**：开发期被替代的代码直接删除（不备份、不留兼容层），删除后同步更新文档。例：`src/modules/visual/` 已于 2026-09-04 删除（仅遗留一个空目录，尚未清理）
5. **知识图谱 vs 知识目录**：实际实现的是"知识目录"（div 层级结构），不是 SVG 知识图谱。文档中必须使用准确术语
6. **6 种知识卡片组件（死代码）**：`src/components/cards/` 下确有 6 个组件与 `KnowledgeCard` 分发器，但**完全未被任何模块引用**（`relatedResults` 死区块已于 2026-09-05 删除）。同类的 `src/components/favorites/FavoritesPanel.tsx` 亦为死代码。按开发期策略需接入主流程或直接删除，待用户决策
7. **文档类型数量**：实际 11 种（含 `general` 通用类型），PRD 中描述为 10 种需修正
8. **AI 服务**：通过 UI 配置 API 密钥（LocalStorage v2 多厂商结构），不再使用环境变量硬编码；预设多家 + 用户自定义厂商
9. **mock fallback**：当前 activeProvider 的 API Key 未配置时自动启用 mock 数据
10. **多语言（i18n）**：`src/i18n/strings/` 以**英文作类型基准**（`xxxEn` → `typeof` 派生类型 → `xxxZh: XxxStrings`）；新增/修改 UI 文案必须同时改 `*En` 与 `*Zh`，漏补会 tsc 报错。数据层文本（厂商名/模型描述/文档模板正文）不迁 i18n，走 `aiProviderTexts.ts` / `docTemplates.ts` 覆盖
11. **内容生成是真流式**：`generateStream`（生产者-消费者，`StreamingJSONParser` + `callModelStream`）；早期的 3 步 `generatePartial` 与"`setTimeout` 分块弹出"的假流式已删除，文档不得再描述为分步/伪流式
12. **流式链路状态诚实处理**：链路失败（网络 / 协议 / 首字节超时 60s）一律**抛错透传**为 `success:false + code`（`STREAM_TIMEOUT` / `STREAM_PROTOCOL`），由 UI 显示具体原因；**不得重新引入"运行时黑名单、失败后降级重发"**这类隐式状态。`hasCompleteJSONObject` 必须复用解析层 `isCompleteJSON`（禁止另写括号配对，避免两套实现漂移）
13. **思考型模型按厂商显式关闭思考**：`DISABLE_THINKING_PARAMS` 按厂商分派（dashscope/siliconflow → `enable_thinking:false`；zhipu → `thinking:{type:'disabled'}`）。**关闭参数字段名逐厂商不同、必须核对官方文档**（传错会 400）；`capabilities.reasoning` 须如实反映型号是否思考型（影响 `temperature` 是否可传）
